# [1110 — Minimal Rotation](https://cses.fi/problemset/task/1110)

**Platform:** CSES  
**Source:** CSES Problem Set — String Algorithms  
**Tags:** Booth, Lyndon, least rotation  
**Difficulty / Rating:** Medium  
**Time limit:** 1.00 s  
**Memory limit:** 512 MB

## Problem Statement

A rotation of a string can be generated by moving characters one after another from beginning to end. For example, the rotations of `acab` are `acab`, `caba`, `abac`, and `baca`.

Your task is to determine the lexicographically minimal rotation of a string.

### Input

The only input line contains a string of length `n`. Each character is one of `a`–`z`.

### Output

Print the lexicographically minimal rotation.

### Constraints

- `1 <= n <= 1e6`

### Examples

**Input**
```
acab
```

**Output**
```
abac
```

---

## What this problem really is

Among all cyclic shifts of `s`, output the lexicographically smallest one. `n <= 1e6` forbids generating and sorting all rotations.

## What to use

| Tool | Why |
|------|-----|
| Doubled string `s+s` | Every rotation appears as a length-`n` window |
| Booth’s least-rotation / Duval-style compare | Find the best start index in `O(n)` |
| Two-candidate elimination | After a mismatch, skip a whole range of starts |

## Approach

**Root idea:** compare rotations without materializing them. Maintain two candidate starting indices `i` and `j`; walk a match length `k` until `s[(i+k)%n]` and `s[(j+k)%n]` differ; the larger side’s candidate (and a block of indices after it) can be discarded.

**Mental picture:** two runners reading the necklace from different beads; the first mismatch tells you which starting bead is worse, and you jump ahead so you never re-test doomed starts.

**Booth-style sketch**

1. Work on `s` (or conceptually on `s+s` with indices `< n`).
2. `i = 0`, `j = 1`, `k = 0`.
3. While both candidates are alive:
   - Compare `s[(i+k)%n]` and `s[(j+k)%n]`.
   - Equal → `k++` (if `k == n`, done).
   - If `s[i+k] > s[j+k]`: advance `i` by `k+1` (and fix so `i != j`); reset `k`.
   - Else symmetrically advance `j`.
4. Let `best = min(i, j)` (the surviving smaller start).
5. Print `s[best..n) + s[0..best)`.

(Implement carefully with the classic Booth `f[]` failure array variant, or a well-tested Duval least-rotation snippet — off-by-ones are easy.)

Suffix array / SA of `s+s` also works but is heavier; Booth is linear and light.

## Walkthrough (on a sample)

`acab` rotations: `acab`, `caba`, `abac`, `baca`.  
Smallest is `abac` (start at index 2).

## Pitfalls

- Comparing full strings for each of `n` starts — `O(n^2)` TLE.
- Printing the start index instead of the rotated string.
- Handling when `s` is periodic (many equal rotations) — any minimal one is fine; algorithm must still terminate correctly.
- Modulo bugs when indexing into `s+s`.

## Complexity

- Time: `O(n)`  
- Space: `O(n)` (or `O(1)` extra besides output)

## Key takeaway

**Least cyclic shift in linear time via Booth / Duval candidate elimination** on the necklace — not by sorting all rotations.
